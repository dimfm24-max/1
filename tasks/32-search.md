## Что есть сейчас

- Поиска нет.
- У этапов и шагов нет описаний. Их вводит задача 08.

## Что сделать

1. Поле поиска в шапке (задача 04).
2. Поиск по названиям и описаниям: цели, этапы, шаги, задачи, заметки.
3. Результаты сгруппированы по виду, совпадение подсвечено.
4. Щелчок открывает объект: цель в дереве, задачу в её дне, заметку.
5. Только данные владельца. Записи из корзины не ищутся. Цели из архива ищутся с пометкой «в архиве».
6. Запрос в PostgreSQL по данным одного человека: `contains` с `mode: 'insensitive'` в Prisma.

## Критерии приёмки

- [ ] «цель» находит «Цель» и «ЦЕЛЬ».
- [ ] Поиск находит слово в описании шага.
- [ ] Чужие данные и записи из корзины не находятся. Интеграционный тест.
- [ ] Ответ — не дольше секунды на аккаунте с тысячами задач.
- [ ] Пустой результат — понятное сообщение.

## Подводные камни

- Регистр кириллицы: `ILIKE` зависит от локали базы. Образ `postgres:18-alpine` — проверь тестом, что «Цель» и «цель» совпадают. Локаль управляемой БД в облаке может отличаться от локальной: проверь и её при запуске (задача 44).
- «ё» и «е»: «ещё» и «еще» не совпадут. Реши, приводить ли «ё» к «е».
- Экранируй `%` и `_` во вводе человека.
- Полнотекстовый поиск с русской морфологией (`to_tsvector('russian', …)`) и триграммы (`pg_trgm`) требуют рукописного SQL в миграции. Это только по явному запросу владельца. Для первой версии хватит `ILIKE`: данные одного человека, индекс по `userId`.
- Запрос при каждом нажатии клавиши — задержка ввода 300 мс и минимум 2 символа.
- Свои поля (задача 33) в поиск не входят: §15 их не называет.
- Поиск читает таблицы трёх контекстов: `goals`, `day`, `notes`. По `docs/ARCHITECTURE.md` контексты общаются через публичный `index.ts`. Рекомендация: каждый из трёх модулей отдаёт свою функцию поиска с фильтром корзины, модуль поиска объединяет результаты. Прямое чтение чужих таблиц через Prisma обойдёт фильтр корзины, как у читателей из задачи 11.
