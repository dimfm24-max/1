# 16. Шаг цели в плане дня

| Поле | Значение |
| --- | --- |
| ТЗ | §3 «День» (задача ссылается на шаг; многодневный шаг — отдельная задача каждый день; шаг попадает в расписание перетаскиванием или кнопкой; автоматически шаги не расставляются), §2 (показатель из выполненных шагов), главный путь из `CHECKLIST.md` |
| Этап сборки | 3. День |
| Зависит от | 08, 13; перетаскивание — 15 |
| Состояние | частично |

## Что есть сейчас

- Задача хранит ссылку на шаг: `Task.stepId`, поле `stepId` в `createTaskRequestSchema`. Сервер проверяет, что шаг принадлежит человеку (`ownedStepId`). Статус цели он не проверяет: шаг закрытой цели ставится в план.
- На экране нельзя поставить шаг в план: нет ни кнопки, ни перетаскивания.
- Выполнение задачи не отмечает шаг и не меняет показатель цели.
- Главный путь из `CHECKLIST.md` («ставит шаг в план на завтра, выполняет его и видит продвижение цели на главном экране») сейчас не проходит.

## Что сделать

1. Кнопка «В план» у шага в разделе «Цели»: дата (сегодня, завтра, другая) и необязательное время. Создаётся задача с названием шага и ссылкой на шаг. Длительность — оценка шага или длительность по умолчанию.
2. Панель «Шаги целей» на экране дня: невыполненные шаги целей в работе. Шаг ставится перетаскиванием на шкалу (задача 15) или кнопкой.
3. Шаг можно поставить в несколько дней. Каждый раз — отдельная задача.
4. Задача показывает цель и шаг, к которым относится.
5. Отметка задачи выполненной спрашивает: «Шаг выполнен целиком?». При «да» шаг закрывается, автоматический показатель цели пересчитывается.
6. Шаг, уже стоящий в плане, помечен датой: «в плане на 23.09.2026».
7. Приложение не расставляет шаги само.

## Критерии приёмки

- [ ] Шаг ставится в план на завтра кнопкой и перетаскиванием.
- [ ] Один шаг стоит в трёх днях как три задачи.
- [ ] После «Шаг выполнен целиком» шаг отмечен, показатель цели вырос, «Сегодня» показывает новое значение.
- [ ] Шаг закрытой цели или цели в корзине поставить в план нельзя.

## Подводные камни

- ТЗ не определяет, закрывает ли выполнение задачи шаг. Многодневный шаг не закрывается одной задачей. Поэтому нужен вопрос, а не автоматика.
- Снятие галочки с задачи не снимает выполнение шага. Шаг снимается отдельно в дереве целей.
- Выполнение шага из задачи меняет дерево целей. Сбрасывай кэш дерева (`goalQueryKeys`) и главной цели, не только кэш дня.
- Шаг закрывается только через модуль `goals`: существующий `PATCH /api/goals/steps/{stepId}` или его публичный `index.ts`. Не пиши `goal_steps.completed_at` из модуля `day`. Пересчёт показателя (`refreshGoal` в `backend/src/modules/goals/infrastructure/goals-repository.ts`) и история показателя (задача 08) живут в `goals`. Прямая запись их обойдёт.
- Задачи шагов, поставленные до закрытия цели, остаются в плане (задача 10). Отметка такой задачи и ответ «Шаг выполнен целиком» вызовут `PATCH /api/goals/steps/{stepId}`, а модуль `goals` отклонит его с `GOAL_CLOSED` (`assertGoalOpen`). Для закрытой цели или цели в корзине не задавай этот вопрос: задача выполняется без шага.
- При ручном способе выполненный шаг показатель не меняет. После «Шаг выполнен целиком» у такой цели предложи записать новое значение (задача 08). Иначе человек не увидит продвижения.
- Удаление шага обнуляет `stepId` у задач (задача 08). Задача остаётся в плане без цели.
- Оценка шага — до 1440 минут (`createStepRequestSchema`). Длительность задачи из оценки укладывается в сутки.
- Флажок задачи есть в двух местах: строка дня `webapp/src/features/day/TaskRow.tsx` и лента «Сегодня» `TodayTimeline` в `webapp/src/features/day/TodayWidgets.tsx` (работа над стилем). Главный путь из `CHECKLIST.md` отмечает шаг на главном экране. Вопрос «Шаг выполнен целиком?» должен работать в обоих местах: одна функция отметки задачи, а не две.

## Решения владельца

Решено владельцем 23.09.2026.

- Нужна ли привязка задачи к цели без шага? **Решение:** нет, только через шаг.
