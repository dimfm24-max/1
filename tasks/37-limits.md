# 37. Ограничения: длина текстов, размер запросов, объём данных

| Поле | Значение |
| --- | --- |
| ТЗ | §14 «Ограничения» (название — 200 знаков; описание — без предела; целей, задач, заметок — без ограничений; файлы — задача 19) |
| Этап сборки | Сквозная возможность |
| Зависит от | задачи, которые добавляют тексты и списки |
| Состояние | частично |

## Что есть сейчас

- Названия ограничены 200 знаками в контрактах целей, задач, подзадач, привычек, заметок, категорий, шаблонов.
- Описания в контрактах без предела.
- Но тело любого запроса к API ограничено `AUTH_BODY_LIMIT_BYTES`: по умолчанию 64 КБ, максимум схемы — 1 МБ (`backend/src/env.ts`, `backend/src/app.ts`). Описание длиннее примерно 64 КБ сервер отклонит с кодом 413.
- Все изменяющие запросы продукта (`/api/users`, `/api/goals`, `/api/day`, `/api/habits`, `/api/notes`, `/api/share`, `/api/uploads`) делят один бюджет частоты `account`: 60 в минуту на адрес клиента. GET не ограничены.
- Раздел «Заметки» и дерево целей отдают все записи одним ответом.

## Что сделать

1. Проверить предел 200 знаков у новых названий: цитата (если у неё есть название), своё поле, вложение. Дело жизни, шаблон, пункт шаблона и категория уже ограничены 200 знаками в контрактах.
2. Поля ввода показывают счётчик у предела.
3. «Описание без предела»: поднять предел тела запроса для текстовых полей до разумной величины и сообщать понятную ошибку. Решение записать в `CHECKLIST.md`.
4. Проверить бюджет частоты на реальном сценарии: мастер, перетаскивание, быстрое добавление, отметки. При необходимости — отдельный бюджет для продуктовых запросов по человеку, а не по адресу.
5. «Без ограничений» по количеству: постраничная выдача заметок, архива, корзины, результатов поиска.
6. Длина текстов без предела ТЗ — решить явно: итог цели, цитата, комментарий (сейчас 2000), имя в комментарии (сейчас 80), единица измерения (сейчас 40).

## Критерии приёмки

- [ ] Каждое название в системе не длиннее 200 знаков: проверка в контракте и на сервере.
- [ ] Описание длиной ровно в предел, выбранный владельцем (по рекомендации 100 000 знаков кириллицей), сохраняется. Описание длиннее получает понятный отказ с пределом.
- [ ] Обычная работа одного человека не упирается в бюджет частоты.
- [ ] Список из 5000 заметок открывается не дольше секунды.

## Подводные камни

- Zod `.max()` считает единицы UTF-16: эмодзи — 2 единицы. PostgreSQL считает символы. На границе 200 знаков возможно расхождение. Рекомендация: считать как Zod, это строже.
- Предел тела запроса защищает сервер. Не снимай его совсем: подними до нужной величины.
- Бюджет частоты по адресу общий для всех людей за одним адресом, например в офисе. Десять знакомых из §20 могут сидеть за одним адресом.
- `AUTH_BODY_LIMIT_BYTES` и бюджет частоты задаются и в Terraform. Меняй значения в обоих местах.
- Предел тела задан в байтах, а кириллица в UTF-8 занимает 2 байта на знак. 64 КБ — около 32 000 русских знаков, а не 64 000. Описание в 100 000 знаков — до 200 КБ.
- Один `AUTH_BODY_LIMIT_BYTES` действует и на `/api/auth/*`, и на продуктовые маршруты (`publicWriteSecurity` в `backend/src/app.ts`). Подъём предела для описаний поднимет его и для входа. Раздели пределы по группам маршрутов.
