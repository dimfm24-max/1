# 41. Удаление аккаунта со всеми данными

| Поле | Значение |
| --- | --- |
| ТЗ | §13 (удаление аккаунта со всеми данными — из настроек, с подтверждением) |
| Этап сборки | 1. Учётная запись (делать после задач, которые добавляют данные и файлы) |
| Зависит от | 19, 30, 40 |
| Состояние | не начато |

## Что есть сейчас

- Удаления аккаунта нет.
- Каскад таблицы `users` удалит строки, но не файлы в хранилище. `docs/STORAGE.md`: «Удаление пользователя также оставляет объект».

## Что сделать

1. «Настройки → Данные → Удалить аккаунт».
2. Предупреждение: что удалится, предложение сначала выгрузить данные (задача 40).
3. Подтверждение паролем.
4. Удаление: все данные, все файлы в хранилище, сессии на всех устройствах, ссылка доступа с комментариями, подписки push, задачи в очереди.
5. Выход и экран «Аккаунт удалён». Письмо об удалении.

## Критерии приёмки

- [ ] После удаления в БД нет строк с id человека. Интеграционный тест по всем моделям с `userId`.
- [ ] Файлы человека удалены из хранилища.
- [ ] Сессии на других устройствах перестают работать.
- [ ] Публичная ссылка перестаёт работать.
- [ ] Регистрация на ту же почту снова возможна.

## Подводные камни

- Ключи объектов хранилища собирай до удаления строк, удаляй объекты после транзакции. Сбой удаления объекта — повтор через очередь, не потеря ключа.
- В очереди `task_outbox` могут лежать письма этому человеку. Отмени их.
- Письмо об удалении (п. 5) ставь после отмены остальных писем, иначе отмена снимет и его. Аккаунта к отправке уже нет: обработчик берёт почту из `payload` и не ищет человека по id. В `payload` — только почта, без имени и других данных.
- Проверка «по всем моделям с `userId`» не видит часть данных:
  - `ShareComment` — связан с человеком через `ShareLink`, своего `userId` нет;
  - `TaskOutbox` — связи с `users` нет по замыслу, почта или id лежат в `payload` (`backend/prisma/schema/outbox.prisma`).
  Добавь их в тест явно.
- Резервные копии production хранят данные ещё какое-то время. Текст о удалении должен быть честным — это обязательство о приватности (AGENTS.md).
- Приватный бакет хранит версии объектов. Terraform удаляет неактуальные версии только через 30 дней (`docs/STORAGE.md`, раздел «Контракт загрузки»). Удалённые фото и вложения физически остаются в облаке ещё до 30 дней. Runtime-ключ Yandex не может удалить версии раньше. Это расходится с ответом `CHECKLIST.md` «файл удаляется вместе с записью». См. вопрос ниже. То же относится к окончательному удалению из корзины (задача 11) и к удалению вложения (задача 19).
- Мобильный клиент работает с тем же сервером. Его токен тоже должен перестать работать.
- Повторная аутентификация: пароль проверяется с ограничением частоты, как вход.
- `User.passwordHash` может быть пустым. Код входа через Apple и Google есть, но выключен (`CHECKLIST.md`, строка «Social sign-in»). Если его включат, у такого аккаунта не будет пароля для подтверждения. Тогда нужен другой способ, например письмо со ссылкой подтверждения.

## Решения владельца

Решено владельцем 23.09.2026.

- Удалять аккаунт сразу или с отсрочкой? **Решение:** сразу, после подтверждения паролем.
- Принять 30 дней хранения удалённых файлов в версиях бакета? **Решение:** да, и честно написать об этом в тексте удаления.
