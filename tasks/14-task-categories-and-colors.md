## Что есть сейчас

- API категорий: создать, изменить, удалить (`/api/day/categories`). У задачи есть `colorOverride`.
- Экрана управления категориями нет. Хуки `useCreateCategoryMutation` и `useDeleteCategoryMutation` в `webapp/src/features/day/queries.ts` нигде не используются.
- Форма новой задачи показывает выбор категории, только если категории уже есть. Создать их негде.
- Свой цвет задачи задать нельзя.
- Удаление категории оставляет задачи без цвета (`onDelete: SetNull`).
- У пункта шаблона `DayTemplateItem.categoryId` нет внешнего ключа. После удаления категории пункт хранит несуществующий id.
- Сервер не проверяет владельца `categoryId`. `createTask`, `updateTask` и `createTemplateItem` в `backend/src/modules/day/infrastructure/day-repository.ts` записывают любой id. Для шага такая проверка есть (`ownedStepId`), для категории — нет. Следствия:
  - задача может ссылаться на категорию другого человека;
  - несуществующий id в задаче даёт ошибку внешнего ключа и ответ 500, а не 404.

## Что сделать

1. «Настройки → Категории»: список, добавить (название и цвет), переименовать, сменить цвет, удалить.
2. Цвет задачи по умолчанию — цвет категории.
3. В карточке задачи (задача 13) — свой цвет и сброс к цвету категории.
4. Удаление категории предупреждает, сколько задач и пунктов шаблонов её используют.
5. Выбор цвета: набор готовых цветов и свой цвет.
6. Проверять владельца `categoryId` при создании и правке задачи и пункта шаблона, как `ownedStepId` проверяет шаг. Чужой или несуществующий id — ответ 404.

## Критерии приёмки

- [ ] Категорию можно создать, переименовать, перекрасить и удалить в настройках.
- [ ] Задача с категорией окрашена в её цвет. Свой цвет задачи важнее цвета категории.
- [ ] Смена цвета категории сразу меняет цвет её задач без своего цвета.
- [ ] После удаления категории применение шаблона работает (см. задачу 17).
- [ ] Задача и пункт шаблона с чужой или несуществующей категорией отклоняются с 404. Интеграционный тест с двумя людьми.

## Подводные камни

- Удаление категории оставляет в пунктах шаблонов висящий `categoryId`. `applyTemplate` в `backend/src/modules/day/infrastructure/day-repository.ts` копирует его в задачу. Внешний ключ задачи отклонит запись, и применение шаблона упадёт. Исправить в этой задаче или в задаче 17: связь с `onDelete: SetNull` через Prisma или очистка пунктов при удалении категории.
- Миграция с новым внешним ключом упадёт, если в базе уже есть пункты с висящим `categoryId`: PostgreSQL проверяет старые строки при `ADD CONSTRAINT`. Такие строки уже могли появиться. Сначала очисти их кодом модуля `day` или отдельным запуском, потом применяй миграцию. Задачи и пункты с чужой категорией внешний ключ не заметит: найди и очисти их тем же запуском. Рукописный SQL в миграции — только по явному запросу владельца (AGENTS.md). Проверь на копии данных и на демо-пользователе из seed.
- Контраст: текст на цветном фоне в светлой и тёмной теме. Цвет используй как полосу или метку, а не как фон текста.
- На ленте дня цвет категории — маленькая точка (задача 45), а тема по умолчанию тёмная (`docs/DESIGN.md`). Тёмно-синий или чёрный цвет человека на карточке `#131915` не виден. Готовые цвета проверь по контрасту не ниже 3:1 с токеном `card` в обеих темах. Своему цвету дай обводку точки или предупреди о плохой видимости.
- Длина названия категории — до 200 знаков (§14), как у других названий.
