## Что есть сейчас

- Есть доставка Expo Push для мобильного приложения: `backend/src/modules/notifications`, очередь `push_notification_outbox`, задание `notifications:process` каждую минуту. В реестре `CHECKLIST.md` — `available`, без ключей.
- Очередь `push_notification_outbox` устроена под Expo:
  - строка без активного Expo-токена сразу завершается как `skipped` с текстом «No active Expo push token registered» (`backend/src/modules/notifications/infrastructure/notification-operations.ts`);
  - строка доставки `PushDelivery` ссылается на Expo-токен;
  - `maintenance:process` каждые 15 минут стирает заголовок и текст завершённых строк (`redactTerminalData`).
- Маршруты `/api/notifications/*` не входят в `createIngressSecurity` в `backend/src/app.ts`: у них нет предела тела и бюджета частоты.
- Уведомлений браузера нет: нет service worker, Web Push, запроса разрешения и настроек.
- Колокольчика в шапке нет.

## Что сделать

1. Центр уведомлений в шапке: список уведомлений с сервера, непрочитанные, «прочитать все», переход к объекту по щелчку.
2. Уведомления браузера:
   - разрешение запрашивается по действию человека — кнопка «Включить уведомления»;
   - доставка через Web Push и service worker;
   - подписка каждого браузера хранится на сервере; при выходе из аккаунта — удаляется.
3. «Настройки → Уведомления»:
   - переключатель для каждого вида из §10;
   - время утреннего приветствия — своя настройка, по умолчанию 08:00, не раньше начала дня (задача 31);
   - время итога дня (задача 20).
   Срок предупреждения о цели хранится у каждой цели (задача 09), не здесь.
4. Защита от потока: не больше одного уведомления браузера в 15 минут на человека. Остальные собираются в одно: «3 новых события».
5. Без разрешения центр в шапке работает. Если разрешение отклонено — подсказка, как включить его в браузере.
6. Сами виды уведомлений — задача 31.
7. Добавить строку в реестр возможностей `CHECKLIST.md`.

## Критерии приёмки

- [ ] После разрешения тестовое уведомление приходит при закрытой вкладке и запущенном браузере.
- [ ] Выключенный вид уведомления не приходит ни в браузер, ни в центр.
- [ ] Пять событий за 5 минут дают не больше одного уведомления браузера за каждые 15 минут: первое уходит сразу, остальные четыре — одним итоговым уведомлением после окна. Все пять — в центре.
- [ ] Протухшая подписка (ответ 404 или 410) удаляется.
- [ ] Повтор задания не отправляет уведомление дважды: dedupe-ключ.
- [ ] Подписка с адресом не из списка push-служб отклоняется. Интеграционный тест.
- [ ] Вход второго аккаунта в том же браузере переносит подписку на него. Уведомления первого аккаунта в этот браузер больше не приходят.

## Подводные камни

- Web Push требует VAPID-ключей. Это секрет: переменные окружения и Terraform, не код.
- Web Push работает только по HTTPS. Локально разрешён `localhost`.
- Service worker должен жить на адресе `webapp`. Он только принимает push и не кэширует приложение: работа без интернета не входит в первую версию (§19).
- Шифрование сообщения (RFC 8291) вручную сложно. Владелец разрешил библиотеку `web-push` 23.09.2026.
- Safari на iPhone показывает Web Push только сайту, добавленному на экран «Домой» (iOS 16.4 и новее). Мобильное приложение отложено — владелец должен знать это ограничение.
- Браузер получает push, только когда он запущен. Уведомление для выключенного компьютера придёт позже или не придёт — зависит от срока жизни сообщения.
- Защита от потока и «новый комментарий — сразу» (§10) противоречат друг другу. Решение владельца: первое уведомление уходит сразу, следующие за 15 минут собираются в одно.
- Текст уведомления виден на экране блокировки. Не помещай туда лишние личные данные.
- Время — по поясу человека (задача 02).
- Очередь: используй существующую очередь и повторы модуля `notifications`, добавь канал браузера. Не делай второй механизм доставки.
- Простое добавление канала не сработает. Сейчас обработчик завершит строку как `skipped`, если у человека нет Expo-токена. Мобильное приложение отложено, поэтому так будет у всех. Обработчик должен выбирать доставку по подпискам всех каналов. Подписке браузера нужна своя таблица и своя строка доставки.
- Центр уведомлений нельзя строить на `push_notification_outbox`: заголовок и текст завершённых строк стираются в ближайший проход `maintenance:process`. Центру нужна своя таблица с прочтением. Её строки попадают в выгрузку (задача 40) и удаляются с аккаунтом (задача 41).
- Новые маршруты подписки и центра подключи к бюджету `account` в `backend/src/app.ts`, как остальные продуктовые маршруты.
- Адрес подписки (`endpoint`) присылает клиент, а сервер отправляет на него запрос. Злоумышленник через API может указать внутренний адрес облака, и сервер сам сделает запрос во внутреннюю сеть (SSRF). Принимай только `https` и хосты известных push-служб: `fcm.googleapis.com`, `updates.push.services.mozilla.com`, `web.push.apple.com`, `*.notify.windows.com`. Ограничь число подписок на человека.
- Список хостов проверь на браузерах первых пользователей (§20), в том числе на Яндекс Браузере. Браузер со своей push-службой получит отказ, и уведомления молча не заработают. Отказ по хосту пиши в журнал: только хост, без полного адреса подписки. По журналу список можно дополнить.
- Подписка принадлежит браузеру, а не аккаунту. Сессия может закончиться без выхода: истёк срок сессии или пароль сброшен с другого устройства. Тогда второй человек входит в том же браузере и регистрирует тот же `endpoint`. Если сервер оставит его и первому человеку, второй увидит на экране чужие уведомления. Держи `endpoint` уникальным: регистрация от нового аккаунта отнимает подписку у прежнего. При выходе вызывай и `unsubscribe()` в браузере, не только удаление на сервере.
- Файл service worker клади в `webapp/public` под постоянным именем, например `/sw.js`. Файлы из `assets/` получают хэш в имени, а выгрузка в Yandex задаёт им `public,max-age=31536000,immutable` (`staticUploadSteps` в `scripts/infra.mjs`). Файлы вне `assets/` получают `max-age=0`: браузер проверит исправленный worker при следующем открытии. Файл в корне охватывает всё приложение.
- Колокольчик не получает события в реальном времени: возможность `Real-time / WebSockets` в реестре `CHECKLIST.md` — `absent`. Обновляй число непрочитанных лёгким запросом при возврате во вкладку и редким опросом, например раз в минуту. GET-запросы не проходят бюджет частоты, поэтому не опрашивай весь список.
