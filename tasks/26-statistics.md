# 26. Статистика: движение целей и доработки

| Поле | Значение |
| --- | --- |
| ТЗ | §6 «Статистика» (выполнение по дням, время по целям, серии привычек, движение целей; за неделю, месяц и год), §19 (отдельная выгрузка статистики не входит) |
| Этап сборки | 6. Статистика |
| Зависит от | 02, 08, 11 |
| Состояние | частично |

## Что есть сейчас

- Модуль `backend/src/modules/statistics` и экран `/app/statistics`.
- Период: неделя, месяц, год. Окна скользящие — решение записано в `CHECKLIST.md`.
- По дням: запланировано, сделано, сгорело.
- Время по целям: длительность выполненных задач, привязанных к шагам. Поле `completedSteps` у цели считает выполненные задачи, а не шаги: `entry.completedSteps += 1` на каждую задачу в `backend/src/modules/statistics/infrastructure/statistics-repository.ts`. Экран подписывает его «шагов».
- Привычки: текущая серия и число отметок.
- Движения целей нет: история показателя не хранится (её вводит задача 08).
- Период показан как `YYYY-MM-DD — YYYY-MM-DD`.
- `today` приходит от клиента.

## Что сделать

1. «Движение целей»: как менялся показатель каждой цели за период. Источник — история показателя (задача 08).
2. Наглядность: графики по дням и по целям. Библиотека `recharts` уже в зависимостях.
3. Даты — в формате ТЗ (задача 01).
4. «Сегодня» вычисляет сервер (задача 02).
5. Исключить записи из корзины (задача 11).
6. Годовой график агрегировать по неделям.
7. Число переносов за период — отдельной цифрой (решение владельца, задача 20).

## Критерии приёмки

- [ ] Для каждой цели виден показатель в начале и в конце периода и путь между ними.
- [ ] Неделя, месяц и год переключаются, данные совпадают с планом дней.
- [ ] Удалённые задачи и цели не учитываются.
- [ ] Шаг, поставленный в три дня, считается в «шагах» цели один раз.
- [ ] Интеграционные тесты: движение целей, граница периода, пояс человека.

## Подводные камни

- История показателя начнётся только после задачи 08. Для прошлых периодов движения не будет. Покажи это честно, а не нулём.
- «Время по целям» — это запланированная длительность выполненных задач, а не фактически потраченное время. Подпиши это на экране.
- Перенесённая задача считается только в новом дне (задача 20).
- Годовой период — 365 точек по дням. Для графика агрегируй по неделям.
- §6 называет «выполнение по дням» для всех периодов. Столбики по неделям прячут отдельные дни года. Рекомендация: для года дополнительно показать дни тепловой картой, как год в «Календаре» (задача 28), из тех же данных.
- Публичная страница (задача 29) не использует этот расчёт. `readPublicProfile` в `backend/src/modules/sharing/infrastructure/sharing-repository.ts` считает своё: число выполненных задач и дней с ними за всё время. Если страница перейдёт на сводку этого модуля, цели с пометкой «личное» не должны просачиваться через время по целям.
- После задачи 16 один шаг стоит в нескольких днях. Тогда `completedSteps` завысит число шагов. Рекомендация: считать различные шаги цели, выполненные в периоде (`GoalStep.completedAt`).
