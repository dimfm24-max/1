# 35. Потеря связи и скорость разделов

| Поле | Значение |
| --- | --- |
| ТЗ | §16 «Поведение и скорость» (план на сегодня мгновенно, остальные разделы до секунды; при потере связи — «нет связи» и повтор при восстановлении), §19 (работа без интернета не входит) |
| Этап сборки | Сквозная возможность |
| Зависит от | 23 |
| Состояние | частично |

## Что есть сейчас

- При ошибке сети экраны показывают «Не удалось загрузить… Проверьте соединение и обновите страницу».
- Сообщения «нет связи» и автоматического повтора нет. `webapp/src/main.tsx` задаёт `retry: false`.
- Замеров скорости нет.

## Что сделать

1. Баннер «Нет связи» при потере сети.
2. После восстановления связи запросы повторяются сами, экраны обновляются.
3. Изменение, которое не дошло до сервера, не теряется молча: оно повторяется или человек видит, что оно не сохранено.
4. Сервер недоступен, а сеть есть — отдельное сообщение.
5. Скорость: «Сегодня» — мгновенно (задача 23); остальные разделы — не дольше секунды. Замер записать в отчёте.

## Критерии приёмки

- [ ] Отключение сети показывает «Нет связи» в течение нескольких секунд.
- [ ] Включение сети убирает баннер и обновляет данные без перезагрузки.
- [ ] Задача, добавленная во время обрыва, не теряется и не задваивается.
- [ ] Обрыв сети не выкидывает человека из аккаунта.

## Подводные камни

- Повтор создания задачи после обрыва может создать две задачи: первый запрос мог дойти. Нужен ключ идемпотентности для создающих запросов или повтор только безопасных запросов.
- `navigator.onLine` ошибается: сеть есть, интернета нет. Опирайся и на ошибки запросов. TanStack Query даёт `onlineManager`.
- Обновление токена во время обрыва не должно завершать сессию: проверь `webapp/src/features/auth/session-coordinator.ts`.
- Service worker для push (задача 30) не кэширует приложение. Работа без интернета не входит в первую версию.

## Проверки

- `bun run test:webapp` — поведение при ошибке сети в запросах
