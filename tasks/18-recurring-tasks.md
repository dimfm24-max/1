## Что есть сейчас

- Повтора нет.

## Что сделать

1. В карточке задачи (задача 13) — «Повтор»:
   - по дням недели: например, пн, ср, пт;
   - по выбранным датам: человек отмечает даты в календаре.
2. Окончание повтора: без конца или до даты.
3. Повторяющаяся задача появляется в каждом подходящем дне.
4. Каждое появление выполняется, переносится и сгорает отдельно.
5. Правка и удаление спрашивают: «только эта» или «эта и следующие».
6. Правило повтора хранить отдельно. Появления — обычные задачи, созданные из правила на ближайшие дни. Создание — при открытии дня и фоновой задачей.

## Критерии приёмки

- [ ] Задача «по пн, ср, пт» появляется в эти дни и только в них.
- [ ] Повтор по выбранным датам появляется ровно в эти даты и только в них.
- [ ] Выполнение, перенос и сгорание одного появления не трогают другие.
- [ ] «Эта и следующие» меняет будущие появления, прошлые остаются.
- [ ] Повторное создание появлений не даёт дублей. Тест на уникальность.
- [ ] Удаление серии отправляет будущие появления в корзину (задача 11).

## Подводные камни

- Уникальность появления — по правилу и исходной дате, а не по текущей дате задачи. Иначе перенесённое появление создастся заново в исходном дне.
- Сгоревшее или удалённое появление нельзя пересоздавать.
- «Удалить навсегда» и очистка корзины (задача 11) стирают строку появления. После этого уникальность по правилу и дате не мешает создать появление снова. Храни у правила список исключённых дат.
- Правило повтора общее с автоприменением шаблонов (задача 17). Шаблонам нужны ещё «каждый день» и «по числам месяца». Сделай одно правило со всеми видами.
- Смена правила: будущие нетронутые появления пересоздать, изменённые вручную — не трогать.
- Далёкое будущее в календаре (задача 28): рекомендация — показывать ожидаемые появления без записи в БД, а записывать только ближайшие дни, например 14.
- Статистика (задача 26) считает только созданные появления. Не создавай появления за прошлые дни, пока человек отсутствовал (задача 21): это завалит его разбором.
- Напоминания (задача 31) — у каждого появления.
- Фоновое создание появлений не требует своего расписания. В Yandex Cloud каждое расписание — отдельный контейнер с таймером (задача 11). Рекомендация: шаг в `maintenance:process`, пачками и с пределом на проход.
- Часовой пояс и начало дня — задача 02.
- У задачи со ссылкой на шаг цели нет «Повтора» (решение владельца). Сервер отклоняет правило повтора для такой задачи.
- Выбранные даты хранятся списком в правиле. Даты в прошлом при создании правила появлений не создают.
