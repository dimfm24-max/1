## Что есть сейчас

- Вход по почте и паролю работает. Пароль не короче 8 символов: `passwordSchema` в `packages/contracts/src/auth.ts`.
- Регистрация сразу создаёт сессию: `register` в `backend/src/modules/auth/application/auth-service.ts`.
- Признака «почта подтверждена» нет: модель `User` в `backend/prisma/schema/base.prisma`.
- Письма уже уходят через очередь `task_outbox`. Образец — сброс пароля. Правила — в `docs/EMAIL.md`.

## Что сделать

1. Добавить в `User` момент подтверждения почты.
2. После регистрации ставить в очередь письмо со ссылкой подтверждения.
3. Сделать страницу подтверждения: ссылка открывает её, сервер отмечает почту подтверждённой.
4. Показывать баннер «Подтверди почту» с кнопкой «Отправить письмо ещё раз».
5. Ограничить частоту повторной отправки.
6. Письмо написать по-русски (задача 01).

## Критерии приёмки

- [ ] После регистрации в очереди появляется письмо. Локально оно печатается в консоль (`EMAIL_DELIVERY=console`).
- [ ] Ссылка одноразовая и имеет срок действия.
- [ ] После подтверждения баннер исчезает во всех вкладках.
- [ ] Повторная отправка ограничена по частоте.
- [ ] Интеграционные тесты покрывают подтверждение, повторную ссылку, истёкшую ссылку и чужой токен.

## Подводные камни

- Хранить только хэш токена, как у сброса пароля. Токен передавать во фрагменте ссылки (`#token=…`), как в `backend/src/modules/auth/infrastructure/password-reset-notifier.ts`: тогда он не попадает в журналы доступа и referrer (`docs/EMAIL.md`, раздел «Безопасность и приватность»).
- Новое поле в существующей таблице будет пустым у старых аккаунтов, например у демо-пользователя из seed. Реши, считать ли их подтверждёнными. Перенос данных — в модуле auth или через seed, не рукописным SQL (AGENTS.md).
- В production `EMAIL_DELIVERY=disabled` делает подтверждение невозможным. При включённом подтверждении нужна реальная доставка.
- Мобильная регистрация (`/api/auth/token/register`) идёт через тот же сервер. Письмо должно уходить и там.
- Не раскрывать через повторную отправку, существует ли аккаунт с этой почтой.
- Регистрация доступна без входа. Каждая регистрация ставит письмо в `task_outbox`. Бюджет `auth` ограничивает только один адрес клиента. Несколько адресов заполнят очередь и задержат настоящие письма. Нужен общий предел, как у сброса пароля: `docs/BACKGROUND_JOBS.md`, раздел «Что может поставить анонимный клиент».
- Кто-то может зарегистрироваться с чужой почтой. Настоящий владелец адреса получит `AUTH_EMAIL_ALREADY_EXISTS`. Ему поможет сброс пароля: письмо доказывает владение почтой. Рекомендация: успешный сброс пароля отмечает почту подтверждённой.
- Если позже появится смена почты, новая почта тоже требует подтверждения.
- Письмо часто открывают на другом устройстве, например в почте на телефоне, где человек не вошёл. Подтверждение должно работать по одному токену, без входа. Размести страницу вне `/app/*`, рядом с `/reset-password`: тогда мастер (задача 07) её не перехватывает.
