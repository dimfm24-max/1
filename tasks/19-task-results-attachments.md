## Что есть сейчас

- У задачи нет результата.
- Приватное хранилище работает: `backend/src/storage`, правила — `docs/STORAGE.md`. Образец загрузки — аватар: `backend/src/modules/uploads`, `webapp/src/features/avatar`.
- Лимит загрузки по умолчанию — 5 МБ (`PRIVATE_STORAGE_UPLOAD_MAX_BYTES` в `backend/src/env.ts`).
- Проверка содержимого знает JPEG, PNG и HEIC (`backend/src/modules/uploads/domain/image-format.ts`). WebP не знает.
- Квоты на человека нет.

## Что сделать

1. Результат задачи — список элементов: текст, фотография (JPEG, PNG, WebP), файл, ссылка.
2. Загрузка — по контракту `docs/STORAGE.md`: билет, прямая отправка в хранилище, завершение с проверкой.
3. Лимиты: 10 МБ на файл, 500 МБ на человека. При превышении — понятное сообщение и остаток места.
4. Показ: фото — исходное изображение без миниатюр (решение из `CHECKLIST.md`); файл — скачивание; ссылка — открывается в новой вкладке.
5. В хранилище имена скрыты за идентификаторами (`CHECKLIST.md`). Исходное имя файла хранится в БД для показа и скачивания.
6. Удаление элемента освобождает место сразу. Удаление задачи освобождает место после корзины (задача 11).
7. «Настройки → Данные» показывают занятое место.
8. Те же вложения — у итога цели (задача 10). Они входят в ту же квоту 500 МБ.

## Критерии приёмки

- [ ] К задаче прикладываются текст, фото, файл и ссылка.
- [ ] Файл 11 МБ отклоняется до загрузки и на сервере.
- [ ] Загрузка сверх 500 МБ отклоняется с понятным сообщением.
- [ ] Две параллельные загрузки не превышают квоту.
- [ ] Фото WebP проходит проверку содержимого. Файл с неверным содержимым отклоняется.
- [ ] Интеграционные тесты с драйвером `filesystem`.
- [ ] К итогу цели прикладываются те же виды вложений.

## Подводные камни

- `PRIVATE_STORAGE_UPLOAD_MAX_BYTES` — один лимит на все загрузки, по умолчанию 5 МБ. Результату нужно 10 МБ. Для production — переменная в Terraform: сейчас её там нет.
- Фото профиля ограничено 5 МБ ещё и контрактом: `AVATAR_MAX_BYTES` в `packages/contracts/src/uploads.ts`. §14 задаёт 10 МБ на любой файл, поэтому фото с телефона больше 5 МБ сейчас отклоняется в нарушение ТЗ. Рекомендация: 10 МБ и для фото профиля — в контракте и в общем лимите. Если владелец оставит 5 МБ, раздели лимит по виду загрузки и запиши отступление от §14 в `CHECKLIST.md`.
- Квота должна учитывать незавершённые загрузки. Иначе параллельные билеты превысят 500 МБ. Резервируй размер при выдаче билета в транзакции.
- Брошенные загрузки. Задание `uploads:pending:cleanup` в `backend/src/jobs.ts` чистит только строки `UserAvatar`. Незавершённая загрузка вложения останется навсегда: её объект займёт хранилище, а резерв — квоту. Человек, который закрыл вкладку во время загрузки, потеряет место без возможности его вернуть. Расширь задание на вложения: сначала объект, потом строка, как для аватара.
- Фото профиля — тоже файл человека (`UserAvatar.byteSize`). Рекомендация: считать его в квоте 500 МБ, чтобы «занятое место» совпадало с реальным.
- Произвольный файл может быть HTML, SVG или скриптом. Открытие такого файла в браузере на своём адресе — XSS. Отдавай файлы только на скачивание: `Content-Disposition: attachment`. Фото показывай через `fetch` и object URL, как аватар (`docs/STORAGE.md`, «Показ приватного файла»).
- Ссылки — только `http` и `https`. Запрет `javascript:`. Атрибуты `rel="noopener noreferrer"`.
- Объекты хранилища удалять после транзакции. Потерянные объекты — риск из `docs/STORAGE.md`; удаление аккаунта (задача 41) и выгрузка (задача 40) должны находить все файлы через БД.
- HEIC браузер не показывает. `CHECKLIST.md` для результатов называет JPEG, PNG и WebP.
- Доступ по ссылке: `CHECKLIST.md` разрешает посетителям видеть файлы открытых разделов. Публичная страница сейчас не показывает задачи, поэтому вложения туда не попадают. Запиши это решение.
