## Что есть сейчас

- API: создание, правка и удаление дела жизни, целей, этапов, шагов. Ручной и автоматический показатель. Главная цель. Модуль `backend/src/modules/goals`, маршруты под `/api/goals`.
- Одно дело жизни на человека. Цель без дела жизни создать нельзя. Первая цель становится главной.
- Автоматический показатель = доля выполненных шагов × целевое число (`backend/src/modules/goals/domain/progress.ts`).
- Экран `/app/goals` (`webapp/src/features/goals`) умеет: создать цель (название, срок, единица, число, способ обновления), добавить этап и шаг, отметить шаг, «Сделать главной», «Удалить» — сразу, без подтверждения.
- Экран не умеет:
  - вводить описание цели;
  - править цель, этап и шаг;
  - удалять этап и шаг;
  - записывать показатель вручную — API `POST /api/goals/goals/{goalId}/progress` есть, кнопки нет;
  - задавать оценку времени шага.
- История показателя не хранится. Статистике «движение целей» (задача 26) не из чего строиться.
- У этапа и шага нет описания.

## Что сделать

1. Правка цели: название, описание, срок (задача 09), единица, целевое число, способ обновления.
2. Правка этапа и шага: название, описание. Удаление — через корзину (задача 11).
3. Оценка времени шага в минутах, необязательная.
4. Ручная запись показателя: поле «сейчас» и кнопка «Записать». Только при ручном способе.
5. История показателя: каждая ручная запись и каждое автоматическое изменение сохраняет строку «момент — значение».
6. Описание у этапа и шага: без предела длины (§14).
7. Главная цель: ровно одна среди целей в работе. Отметку можно перенести.
8. Все названия — не длиннее 200 знаков.
9. Порядок этапов и шагов — перетаскиванием. Библиотека `@dnd-kit` разрешена (задача 15). Порядок хранится в `position`.
10. Начальное значение у числовой цели. Удобная форма: при создании и правке человек пишет «сколько сейчас» и «сколько нужно». Первое число становится начальным. Рост или снижение приложение понимает само. Продвижение = (текущее − начальное) / (целевое − начальное).

## Критерии приёмки

- [ ] Любое поле цели, этапа и шага меняется на экране и сохраняется.
- [ ] При ручном способе человек записывает число, полоса и процент обновляются.
- [ ] При автоматическом способе число меняется от выполненных шагов, ручная запись недоступна.
- [ ] Каждое изменение показателя появляется в истории.
- [ ] Удаление этапа предупреждает, сколько шагов удалится.
- [ ] Цель «60 килограммов» с начальным значением 80 показывает 0 % при 80, 50 % при 70 и 100 % при 60.
- [ ] Порядок этапов и шагов меняется перетаскиванием и сохраняется после перезагрузки.

## Подводные камни

- Смена способа с ручного на автоматический перезапишет число. Предупреди человека. Обратная смена оставляет последнее вычисленное число.
- Смена целевого числа при автоматическом способе пересчитывает показатель. Это тоже строка истории.
- Добавление и удаление шага при автоматическом способе тоже меняет показатель: доля выполненных шагов падает или растёт. Это строки истории. «Движение целей» (задача 26) покажет спад после добавления шагов. Подпиши причину, чтобы спад не выглядел как откат.
- Показатель считается только от нуля вверх: `goalCompletionRatio` в `backend/src/modules/goals/domain/progress.ts` делит текущее значение на целевое. Пример из §2 «60 килограммов» — обычно снижение веса, например с 80. Человек записывает «78», и полоса сразу показывает 100 %: 78 / 60 обрезается до 1. Начального значения в модели нет. Владелец решил его добавить (п. 10). Оно затрагивает мастер (задача 07), движение целей (задача 26) и публичную страницу (`publicGoalSchema`, задача 29). Процент считают ещё два места в клиенте: `percentOf` в `webapp/src/features/goals/goal-view.ts` и своя формула в `webapp/src/features/sharing/pages.tsx`. Рекомендация: одна формула. Сервер отдаёт долю в ответе, клиенты её только показывают.
- Целевое число 0 проходит проверку контракта (`valueSchema` — `min(0)`). Такая цель всегда показывает 0 %. Требуй, чтобы целевое число отличалось от начального значения. Если начального значения нет — было больше нуля.
- Удаление шага обнуляет `Task.stepId` у задач дня (`onDelete: SetNull`). Задачи теряют связь с целью. Статистика «время по целям» перестаёт считать это время. Предупреди, если на шаг ссылаются задачи.
- Цель с нулём шагов при автоматическом способе показывает 0 %. Покажи подсказку «добавь шаги».
- `targetValue` хранится как `Decimal(14,3)`, в JSON приходит числом. Округление при показе — до разумного числа знаков.
- В `backend/src/modules/goals/infrastructure/goals-repository.ts` изменение шага (`updateStep`) и пересчёт показателя (`refreshGoal`) — отдельные запросы без транзакции: запись шага, чтение всех шагов, запись показателя. Две одновременные отметки шагов одной цели могут записать устаревшее число: запрос, который прочитал шаги раньше, пишет последним. С историей показателя ошибка останется и в истории. Задача 16 добавляет второй путь отметки шага — с экрана дня. Рекомендация: изменение шага, пересчёт и строка истории — в одной интерактивной транзакции Prisma с уровнем `Serializable` и повтором при конфликте.
- История растёт на одну строку за изменение. Это немного, но выгрузка (задача 40) и удаление аккаунта (задача 41) должны её учитывать.
- Удаление цели — через корзину (задача 11), не сразу.
- «Только для числовых выражений» — слова владельца о начальном значении. Трактовка: начальное значение есть у цели с ручным способом, где человек записывает число. При автоматическом способе показатель — доля выполненных шагов, начальное значение не используется. Если трактовка неверна, уточни у владельца до начала задачи.

## Решения владельца

Решено владельцем 23.09.2026.

- Удалять этапы и шаги сразу или через корзину? **Решение:** через корзину (задача 11).
- Нужен ли порядок этапов и шагов перетаскиванием? **Решение:** да.
- Нужны ли цели с убывающим показателем, например «60 килограммов» при весе 80? **Решение:** да, у цели есть начальное значение. Только для числовых целей, в удобной для человека форме (п. 10).

- Трактовка «только для числовых целей». **Сделано по рекомендации, ждёт подтверждения владельца:** начальное значение есть у цели с ручным способом. При автоматическом способе показатель — доля выполненных шагов.
