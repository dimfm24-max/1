# 39. Метрика «ведёт день 5 дней из 7»

| Поле | Значение |
| --- | --- |
| ТЗ | §20 «Как поймём, что продукт работает» (человек возвращается и ведёт день хотя бы 5 дней из 7) |
| Этап сборки | Сквозная возможность |
| Зависит от | 21 |
| Состояние | не начато |

## Что есть сейчас

- Метрики нет. Аналитики нет. Раздела администратора нет.
- Дни активности человека записывает задача 21.

## Что сделать

1. Взять определение «вёл день» из задачи 21.
2. Задание `metrics:retention` в `backend/src/jobs.ts`. Локально — `bun run --cwd backend start:cron -- metrics:retention`. Задание пишет в лог:
   - сколько людей активны;
   - сколько из них вели день 5 и более дней из последних 7;
   - распределение по числу дней.
3. Вывод — только числа, без почты, имён и id.
4. Описать запуск задания в `docs/COMMANDS.md` и расписание, если оно есть, в `docs/BACKGROUND_JOBS.md`.

## Критерии приёмки

- [ ] Задание выдаёт числа на локальной базе и на тестовых данных.
- [ ] В выводе нет личных данных.
- [ ] Тест на подсчёт: 5 из 7, 4 из 7, пояс человека.

## Подводные камни

- «День» — по поясу и началу дня человека (задача 02), не по UTC.
- Фоновое обновление токена — не активность (задача 21).
- Задание только читает production-базу.
- Локальный скрипт до production-базы не дотянется. В Yandex Cloud у кластера нет публичного адреса (`assign_public_ip = false` в `infra/yandex/production/foundation.tf`). В DigitalOcean базу закрывает firewall. Не открывай доступ к базе ради метрики. Поэтому метрика — задание в облаке, а результат — числа в логе. Запуск — по расписанию, например раз в неделю: строка в `backend/src/job-schedules.json`. В Yandex Cloud это отдельный контейнер с таймером (задача 11).
- Данных до задачи 21 нет. Можно восстановить активность из `completedAt` задач — по желанию.
