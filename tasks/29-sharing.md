## Что есть сейчас

- Модуль `backend/src/modules/sharing`, настройки `/app/share`, публичная страница `/p/{token}` без входа.
- Одна ссылка на человека. Владелец включает разделы: цели, привычки, статистика.
- Смена адреса ломает прежнюю ссылку сразу. Закрытие удаляет страницу вместе с комментариями.
- Любой посетитель оставляет комментарий, имя вводит сам.
- Не хватает:
  - пометки «личное» у цели: колонка `Goal.isPrivate` есть, но контракт и экран её не меняют;
  - фото владельца на странице: есть только имя (`publicProfileResponseSchema`);
  - списка комментариев у владельца и их удаления на экране: API `DELETE /api/share/comments/{commentId}` есть, кнопки нет. Запроса «комментарии владельца» нет: список приходит только с публичной страницы по токену;
  - уведомления владельцу о новом комментарии;
  - отдельного ограничения частоты для публичных комментариев. Сейчас `/api/share/*` проходит общий бюджет `account` (60 изменений в минуту на адрес клиента, `backend/src/app.ts`). Посетитель тратит тот же бюджет, что и владелец за тем же адресом.
- Название дела жизни (`lifeGoalTitle`) видно посетителю всегда, даже когда раздел «Цели» выключен: `readPublicProfile` в `backend/src/modules/sharing/infrastructure/sharing-repository.ts`. По §6 дело жизни — часть дерева целей.
- Публичная «Статистика» — два числа за всё время: выполненные задачи и дни с ними. Их считает `readPublicProfile`, а не модуль `statistics`.

## Что сделать

1. Пометка «личное» в карточке цели. Личная цель не видна на публичной странице.
2. Имя и фото владельца на странице.
3. У владельца — список комментариев и удаление любого из них. Для списка — отдельный запрос владельца, не публичная страница.
4. Название дела жизни показывать только при включённом разделе «Цели».
5. Уведомление о новом комментарии: в центре уведомлений и в браузере (задачи 30, 31).
6. Отдельный бюджет частоты для публичных комментариев по адресу посетителя и по ссылке. Существующий модуль `backend/src/rate-limit`.
7. Настройки доступа — подраздел «Настроек» (задача 04).
8. Посетитель видит цели всех статусов — в работе, завершённые и брошенные, кроме личных. Статус подписан.
9. Включить доступ можно только с подтверждённой почтой (задача 05).
10. «Статистика» для посетителя: выполнение по дням за неделю, месяц и год. Время по целям и серии привычек — только при открытых «Целях» и «Привычках», без личных целей.

## Критерии приёмки

- [ ] Личная цель не видна посетителю ни в списке целей, ни в статистике.
- [ ] Посетитель видит имя и фото владельца.
- [ ] После смены адреса или закрытия ссылки фото по старому адресу не открывается.
- [ ] Владелец удаляет комментарий, посетитель его больше не видит.
- [ ] Частая отправка комментариев отклоняется.
- [ ] Страница не раскрывает почту и id владельца.
- [ ] При выключенном разделе «Цели» посетитель не видит ни целей, ни названия дела жизни.
- [ ] Пометку «личное» можно поставить и снять и у закрытой цели в архиве. Интеграционный тест.
- [ ] Брошенная цель видна посетителю с пометкой «брошена». Личная цель не видна.

## Подводные камни

- Фото лежит в приватном хранилище. Нужна выдача по токену ссылки с короткой подписью. После отзыва ссылки выдача прекращается.
- API отдаёт `Cross-Origin-Resource-Policy: same-origin`. Показывай фото через `fetch` и object URL, как аватар (`docs/STORAGE.md`).
- Время по целям и итоги статистики на странице не должны включать личные цели.
- Разделы открываются по отдельности, а статистика владельца (§6) называет цели и привычки. Если статистика открыта, а цели скрыты, «время по целям» раскроет названия целей. Если скрыты привычки, «серии привычек» раскроют названия привычек. Показывай в статистике только то, что открыто в своём разделе. Сейчас утечки нет: публичная статистика — два числа без названий. Риск появится, когда страница получит больше статистики (п. 10).
- Имя в комментарии — утверждение автора, не личность. Подпиши это.
- Комментарий выводится как текст. React экранирует разметку — не используй вставку HTML.
- «Сразу» для уведомления о комментарии и защита от потока (задача 30) — правило там.
- Цели из корзины (задача 11) не показываются.
- `GET /api/share/public/{token}` открыт без входа, а бюджет частоты пропускает GET. Каждый запрос читает все выполненные задачи владельца за всё время, все отметки привычек и все комментарии. Ограничь выборку: считай числа в БД, а не в памяти; комментарии отдавай постранично.
- Публичная страница передаёт `today` из браузера посетителя. Серии привычек владельца считаются по часам посетителя. После задачи 02 день считает сервер по поясу владельца.
- Адрес `/p/{token}` сам даёт доступ. Запрети индексацию страницы: `<meta name="robots" content="noindex">`. Задай политику referrer `no-referrer`, чтобы переход по внешней ссылке не передавал адрес. `webapp` отдаёт один `index.html` на все адреса, поэтому обе метки ставит экран публичной страницы.
- Строка «Public sharing» реестра в `CHECKLIST.md` говорит, что цель можно пометить личной. Экран и API этого не умеют: колонку `Goal.isPrivate` меняет только прямая запись в БД. Исправь строку реестра в этой задаче.
- Имя при регистрации необязательно: `User.displayName` может быть пустым. Тогда страница не подписана именем, как требует §11. Рекомендация: при включении доступа по ссылке просить имя, если его нет.
- Пометку «личное» нельзя провести через `updateGoal` в `backend/src/modules/goals/infrastructure/goals-repository.ts`: он начинается с `assertGoalOpen` и отклоняет правку закрытой цели. Публичная страница показывает цели всех статусов — так решил владелец. Человек не сможет спрятать завершённую цель, не вернув её в работу. Сделай отдельное действие «личное» без проверки статуса. Флаг меняет только видимость, а не саму цель.
- Фото в формате HEIC посетитель в Chrome и Firefox не увидит. Правило для фото профиля — в задаче 06.
- Кнопка «Закрыть доступ» удаляет строку `ShareLink`, а каскад — все комментарии (`disable` в `backend/src/modules/sharing/infrastructure/sharing-repository.ts`). Удаление идёт одним щелчком, без подтверждения, и его нельзя отменить. Отозвать старый адрес можно и без потерь: «Сменить адрес» (`rotate`) сохраняет комментарии. Рекомендация: закрытие доступа спрашивает подтверждение и называет число комментариев, которые удалятся.

## Решения владельца

- Включать доступ по ссылке только с подтверждённой почтой? **Решение:** да (задача 05).
- Что посетитель видит в «Статистике»? **Решение:** выполнение по дням за неделю, месяц и год. Время по целям и серии привычек — только при открытых «Целях» и «Привычках», без личных целей.
