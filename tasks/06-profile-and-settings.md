## Что есть сейчас

- `/app/settings` — только тема оформления и выход, по-английски.
- `/app/profile` — имя, фото, почта только для чтения, по-английски.
- API дня умеет менять начало дня, длительность по умолчанию, тон, дату рождения и продолжительность жизни (`PATCH /api/day/settings`). Экрана для начала дня, длительности и тона нет.
- Дату рождения и продолжительность жизни меняют на экране горизонта.
- Продолжительность жизни по умолчанию не задана: поле пустое (`lifeExpectancy` nullable).
- Настройки принадлежат модулю `day`: модель `UserSettings` в `backend/prisma/schema/day.prisma`.

## Что сделать

1. Каркас раздела «Настройки» с подразделами:
   - Профиль — эта задача;
   - Тон — эта задача;
   - День: начало дня, длительность по умолчанию — эта задача;
   - Горизонт: дата рождения, продолжительность жизни — эта задача;
   - Оформление — задача 34;
   - Уведомления — задача 30;
   - Категории — задача 14;
   - Шаблоны дня — задача 17;
   - Цитаты — задача 22;
   - Свои поля — задача 33;
   - Доступ по ссылке — задача 29;
   - Данные: корзина, выгрузка, удаление аккаунта — задачи 11, 40, 41.
2. Профиль: имя, фото, почта, часовой пояс (задача 02).
3. Тон: четыре варианта с примером фразы для каждого (задача 03).
4. Начало дня (по умолчанию 00:00) и длительность задачи по умолчанию (30 минут).
5. Продолжительность жизни по умолчанию — 80 лет.
6. Каждая настройка сохраняется сразу и применяется без перезагрузки.

## Критерии приёмки

- [ ] Все подразделы из §6 есть в «Настройках», по-русски.
- [ ] Смена начала дня сразу меняет «сегодня» по правилу задачи 02.
- [ ] Новая задача без явной длительности получает длительность из настроек.
- [ ] Продолжительность жизни — 80 лет, пока человек не указал другое.
- [ ] Часовой пояс можно выбрать из списка с поиском.

## Подводные камни

- Настройки стали общими: их читают день, горизонт, мастер, уведомления и оформление. Сейчас ими владеет модуль `day`. Реши владельца в этой задаче. Рекомендация: отдельный контекст настроек или модуль `users`, а `day` читает настройки через публичный `index.ts`. Не размножай источники настроек.
- Смена начала дня меняет прочтение уже запланированных задач (задача 02). Покажи предупреждение.
- Смена длительности по умолчанию не меняет уже созданные задачи.
- Почта в профиле только для чтения, пока нет смены почты. Смена почты требует подтверждения (задача 05).
- Оформление сейчас хранится в браузере. Задача 34 переносит его в профиль.
- Смена владельца настроек не должна трогать таблицу. Перенеси модель в файл схемы нового модуля и сохрани `@@map("user_settings")` и имена столбцов. Если переименовать модель вместе с таблицей, Prisma создаст новую таблицу и удалит старую: настройки всех людей пропадут. Проверь SQL миграции. Старый маршрут `PATCH /api/day/settings` оставь на один релиз: его вызывают открытые вкладки.
- Фото профиля. Webapp принимает HEIC и не принимает WebP: `acceptedFileTypes` в `webapp/src/features/avatar/AvatarPanel.tsx`. Backend хранит байты без преобразования, а Chrome и Firefox HEIC не показывают (`docs/STORAGE.md`, раздел «Изображения и оптимизация»). Такое фото не видно в шапке (задача 04) и на публичной странице (задача 29, §11). `CHECKLIST.md` для изображений называет JPEG, PNG и WebP. Рекомендация: принимать JPEG, PNG и WebP. HEIC преобразовывать в браузере до загрузки, а если браузер не может его прочитать — отклонять с понятным текстом. Там, где фото не загрузилось, показывать инициалы.
