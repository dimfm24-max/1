# 09. Срок цели: выбор в календаре, предупреждение, наступление срока

| Поле | Значение |
| --- | --- |
| ТЗ | §2 «Срок цели» |
| Этап сборки | 2. Цели |
| Зависит от | 02, 08 |
| Состояние | сделано |

## Что есть сейчас

- Срок у цели обязателен: API и форма требуют дату. Форма использует нативный `<input type="date">`.
- Карточка цели показывает «осталось N дней», «последний день» и метку «Просрочена».
- Нет настройки «предупреждать за N дней», нет предупреждения и нет вопроса после срока.
- API не запрещает срок в прошлом.

## Что сделать

1. Выбор срока — календарём (§2), в формате ТЗ (задача 01).
2. Срок не может быть раньше сегодняшнего дня человека (задача 02) при создании, продлении и возврате из архива.
3. У каждой цели своё поле «Предупреждать о сроке за N дней», по умолчанию 3. Поле — в форме цели (задача 08). Мастер (задача 07) ставит 3 без вопроса.
4. Предупреждение в приложении: на «Сегодня» (задача 23) и в карточке цели, когда до срока N дней или меньше.
5. Уведомление браузера о приближении срока — задача 31.
6. После срока, если цель в работе, приложение при входе спрашивает про каждую такую цель:
   - «Продлить» — новый срок в календаре;
   - «Закрыть» — окно итога (задача 10);
   - «Отказаться» — окно итога (задача 10).

## Критерии приёмки

- [ ] Срок нельзя поставить в прошлое.
- [ ] Предупреждение появляется ровно за N дней и держится до срока.
- [ ] На следующий день после срока при входе появляется вопрос.
- [ ] Каждый вариант ответа меняет цель и убирает вопрос.
- [ ] Несколько просроченных целей — один экран со списком, не цепочка окон.
- [ ] Две цели с разными N предупреждают каждая в свой срок.

## Подводные камни

- Когда срок «наступил»: в день срока или на следующий? Рекомендация: день срока — «последний день», вопрос — со следующего дня.
- Закрытие окна без ответа. Рекомендация: спросить снова при следующем входе. Не прятать вопрос навсегда.
- Вопрос о сроке, итог дня (задача 20) и сводка после отсутствия (задача 21) могут появиться одновременно. Нужен один порядок показа. Рекомендация: один экран «разбора» с разделами.
- Срок — дата без времени по правилу задачи 02. Иначе предупреждение сработает на день раньше в поясе с отрицательным сдвигом.
- Проверка «не в прошлом» нужна на сервере, а не только в форме. Мастер (задача 07) использует ту же проверку.
- Проверяй срок, только когда он меняется. Форма правки просроченной цели может прислать прежний срок вместе с новым названием. Такой запрос не должен падать.
- Сейчас `reopenGoal` в `backend/src/modules/goals/infrastructure/goals-repository.ts` принимает любой срок, а `updateGoal` — любой новый срок. Проверку добавь в оба пути.
- N хранится у цели, а не в настройках: так решил владелец. Новое поле цели добавляй совместимо с открытыми вкладками (общее правило о `.strict()` в `tasks/README.md`).

## Решения владельца

Решено владельцем 23.09.2026.

- Сколько дней N по умолчанию? **Решение:** 3 дня.
- N — одна настройка на все цели или своя у каждой? **Решение:** своя у каждой цели.
