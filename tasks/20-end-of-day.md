# 20. Конец дня: перенос, сгорание, вечерний итог

| Поле | Значение |
| --- | --- |
| ТЗ | §3 «Конец дня» |
| Этап сборки | 3. День |
| Зависит от | 02, 06, 13 |
| Состояние | частично |

## Что есть сейчас

- У невыполненной задачи две кнопки в `webapp/src/features/day/TaskRow.tsx`:
  - «На завтра» — перенос на день после просматриваемого дня;
  - «Отпустить» — задача сгорает и остаётся в истории с меткой «Сгорела».
- Перенесённая задача помечена «Перенесена с …» (поле `movedFrom`).
- Выбрать другую дату переноса нельзя. API принимает любую дату (`resolveTaskRequestSchema`).
- Вечернего итога нет. Карточка «Итог дня» на экране — только счётчики.

## Что сделать

1. Перенос: по умолчанию на завтра; можно выбрать дату в календаре.
2. «Завтра» — завтра относительно сегодняшнего дня человека (задача 02), а не относительно даты задачи.
3. Вечерний итог: за час до конца дня приложение показывает окно:
   - что сделано;
   - что осталось;
   - для каждой невыполненной задачи — «перенести» (завтра или дата) или «сгорает»;
   - «перенести все на завтра» одним действием.
4. Конец дня — следующее начало дня (задача 02). Время итога настраивается, по умолчанию — за час до конца.
5. Если человек не ответил вечером, вопрос о прошедшем дне появляется при следующем входе.
6. Сгоревшие задачи остаются в истории с пометкой.
7. Уведомление браузера «Итог дня» — задача 31. Текст — тоном человека (задача 03).

## Критерии приёмки

- [ ] Перенос на выбранную дату работает.
- [ ] Задача недельной давности переносится на завтрашний день, а не в прошлое.
- [ ] Итог появляется в настроенное время, если приложение открыто, и при следующем входе, если нет.
- [ ] Ответ на итог сохраняется: окно не появляется дважды за один день.
- [ ] Незавершённые задачи никогда не сгорают без решения человека.

## Подводные камни

- Сейчас «На завтра» для старой задачи ставит её на день после её даты. Для задачи недельной давности это снова прошлое.
- Поле `movedFrom` хранит только последнюю дату. История нескольких переносов теряется. Рекомендация: этого достаточно для первой версии.
- Статистика (задача 26): перенесённая задача считается только в новом дне. В исходном дне следа нет. Реши, считать ли перенос в исходном дне. Рекомендация: показывать число переносов в статистике дня.
- Где хранить «итог за дату показан и разобран»: нужен признак на сервере, иначе окно повторится на другом устройстве.
- Итог, вопрос о сроке цели (задача 09) и сводка после отсутствия (задача 21) могут совпасть. Нужен один экран разбора.
- Повторяющиеся задачи (задача 18) переносятся как отдельные появления.
- Времени итога нужен экран, а подраздел «Уведомления» наполняет более поздняя задача 30. Поставь настройку в подраздел из каркаса «Настроек» задачи 06. Отсюда зависимость от 06.
- Выпуск задачи. У существующих аккаунтов в прошлых днях уже лежат невыполненные задачи за всё время: кнопки «На завтра» и «Отпустить» необязательны. Вопрос о прошедшем дне (п. 5) не должен поднять их все при первом входе после выпуска. Рекомендация: спрашивать о днях не раньше даты выпуска. Более старые задачи остаются в истории как есть.
